# Scientific Data

Atlas separates data from rendering. The renderer consumes normalised local datasets. It never contacts an astronomy service while running, and it never holds astronomical values of its own. This document is the methodology reference. The numbers it quotes are generated: see `docs/DATA_PROVENANCE.md` and `docs/DATA_QUALITY_REPORT.md`.

## 1. Catalogues integrated

| Source | Role | Release | Status |
|---|---|---|---|
| **ESA Gaia DR3** | Astrometry and photometry (positions, parallax, proper motion, G/BP/RP) | DR3, 13 June 2022; reference epoch J2016.0; ICRS | **Integrated, retrieved live** from the Gaia archive TAP service on 2026-11-12 |
| **Gaia archive cross-match tables** | Hipparcos number (`gaiadr3.hipparcos2_best_neighbour`), GSP-Phot effective temperature (`gaiadr3.astrophysical_parameters`) | DR3 | Integrated in the same query |

### 1.1 Gaia query
Submitted as an asynchronous TAP job to `https://gea.esac.esa.int/tap-server/tap`. The exact text is generated by `buildGaiaQuery()` (`src/data/ingestion/gaia.ts`) and stored in `docs/DATA_PROVENANCE.md`:

```sql
SELECT g.source_id, g.ref_epoch, g.ra, g.ra_error, g.dec, g.dec_error, g.parallax, g.parallax_error,
       g.pmra, g.pmra_error, g.pmdec, g.pmdec_error,
       g.phot_g_mean_mag, g.phot_g_mean_flux_over_error, g.phot_bp_mean_mag, g.phot_bp_mean_flux_over_error,
       g.phot_rp_mean_mag, g.phot_rp_mean_flux_over_error, g.ruwe, g.astrometric_params_solved,
       g.visibility_periods_used, g.astrometric_excess_noise, g.duplicated_source,
       h.original_ext_source_id AS hip_id, h.angular_distance AS hip_sep_arcsec,
       a.teff_gspphot, a.teff_gspphot_lower, a.teff_gspphot_upper
FROM gaiadr3.gaia_source AS g
LEFT OUTER JOIN gaiadr3.hipparcos2_best_neighbour AS h ON g.source_id = h.source_id
LEFT OUTER JOIN gaiadr3.astrophysical_parameters AS a ON g.source_id = a.source_id
WHERE g.phot_g_mean_mag < 6.5 OR (g.parallax >= 25 AND g.parallax_over_error >= 5)
ORDER BY g.source_id
```

**Selection criteria and why.** The subset is the union of two documented sets:
- *Bright set:* every source with G < 6.5 (the naked-eye sky), **with no parallax-quality cut**, so real missing and unreliable parallaxes are present and exercised.
- *Nearby set:* parallax >= 25 mas (distance <= 40 pc) with parallax/error >= 5.

The result is 35,325 rows (about 10 MB of CSV; the download took about 45 s when observed once), large enough to make the stellar neighbourhood visually rich and small enough to ship. Rows are ordered by `source_id` so a repeat import yields identical row order.

### 1.2 SIMBAD access
Atlas asks the primary service first and falls back to the official CfA mirror, recording which host served the data. On 2026-11-12 the primary host (`simbad.cds.unistra.fr`) answered every `/simbad/` request with a "Page unavailable" page from the build sandbox, while the CDS front page itself responded. The CfA mirror (`simbad.cfa.harvard.edu`) answered, so **all SIMBAD data in this dataset came from the mirror**. This is recorded in the dataset manifest and in `docs/DATA_PROVENANCE.md`. Nothing was synthesised when the primary failed.

Matching is by **exact identifier** (`Gaia DR3 <source_id>` in SIMBAD's `ident` table), 250 ids per request, never by position, so a neighbouring star cannot be mis-assigned. SIMBAD supplies identifiers and classification only and never replaces Gaia astrometry or photometry.

## 2. Data model

`src/data/schema.ts`. Every quantity is a `Measurement`:

| Field | Meaning |
|---|---|
| `value`, `unit` | Value in the unit the catalogue published (mas, mas/yr, deg, mag, K, ...). Allowed units are listed in `src/data/validate.ts`; an unknown unit is rejected, never guessed |
| `uncertainty`, `uncertaintyUnit` | 1-sigma, in the published unit (e.g. RA in deg with its error in mas) |
| `kind` | `observed`, `derived`, `modelled` or `hypothetical` (see below) |
| `source` | catalogue key, release, record id (the Gaia `source_id`), URL, retrieval date |
| `transformations` | ordered steps from the original values. **Required for derived values** (enforced by the validator) |
| `epoch` | e.g. `J2016.0` |

**The four categories are never mixed:**

| Kind | Meaning | Examples here |
|---|---|---|
| observed | published by the catalogue as a measurement or fit result; Atlas does not alter it | RA, Dec, parallax, proper motion, G/BP/RP magnitudes, RUWE (a fit statistic computed by Gaia DPAC) |
| derived | computed from observed values plus stated assumptions | distance (1000/parallax), BP-RP colour, absolute G magnitude, galactic l and b, magnitude uncertainty from flux S/N |
| modelled | an estimate from a scientific model fitted to data | GSP-Phot effective temperature |
| hypothetical | proposed, not confirmed | none in this dataset |

**Missing is not zero.** An unavailable quantity is absent from `CelestialObject.measurements` and listed in `unavailable` with a reason. In the stored dataset it is `null`. A genuine 0 (for example a proper motion of exactly 0) is preserved as 0 and displayed as 0. Both behaviours are tested.

**Provenance is per measurement logically, per dataset physically.** 35,325 records times 25 columns would repeat the same provenance 880,000 times, so the stored file keeps one manifest (catalogue, release, ADQL, retrieval time, checksums) and per-record identifiers. `GaiaCatalogue.toObject()` assembles a fully sourced `Measurement` for every value on demand, which is what the inspector shows.

## 3. Coordinates and conventions

All of this is implemented in `src/core/astro/` and tested in `tests/astro.test.ts`.

| Topic | Convention |
|---|---|
| Reference frame | ICRS. Gaia positions are ICRS barycentric. |
| Epoch | **J2016.0** for every Gaia position. No proper-motion propagation is applied anywhere in the dataset or renderer. `propagateProperMotion()` exists (exact great-circle step, zero radial velocity assumed) but is unused by the renderer. |
| Angles | RA and Dec in **degrees**. RA in [0, 360), Dec in [-90, 90]. Radians appear only inside trigonometric calls. |
| Small angles | Uncertainties of position and parallax are in **milliarcseconds** exactly as Gaia publishes them. `ra_error` is the error on RA*cos(Dec). |
| Proper motion | mas/yr. `pmra` is mu_alpha* = mu_alpha cos(delta) as published. |
| Cartesian axes | ICRS-aligned: +X toward (RA 0, Dec 0), +Y toward (RA 90 deg, Dec 0), +Z toward the north celestial pole. Right-handed. |
| Scene length unit | parsecs inside the star layer; metres in the frame tree (`METRES_PER_PARSEC = 3.0856775814913673e16`, IAU 2015). |
| Galactic coordinates | The Hipparcos/Gaia ICRS-to-Galactic rotation matrix. Verified in tests: the Galactic centre direction is RA 266.405, Dec -28.936 and the north pole is RA 192.859, Dec +27.128. |
| Frames | `src/data/catalogue/frames.ts` defines `milky-way` and `stellar-neighbourhood` (origin: the Sun). The Sun is placed 8.178 kpc from the centre (GRAVITY 2019) on the line to the Galactic centre; its roughly 20 pc height above the plane is ignored. Frame radii are visualisation extents, not astronomical boundaries. |

## 4. Parallax and distance

`parallaxToDistance()` in `src/core/astro/parallax.ts`:

| Class | Rule | Distance produced? |
|---|---|---|
| missing | no parallax in the catalogue | **No** |
| invalid | parallax present but its uncertainty is missing or non-positive | **No** |
| unreliable | parallax <= 0, or parallax/error < 5 | **No** |
| marginal | 5 <= parallax/error < 10 | Yes, flagged, drawn dimmer |
| reliable | parallax/error >= 10 | Yes |

`d = 1000 / parallax[mas]` parsecs, with the 1-sigma interval 1000/(parallax +/- error) and first-order sigma = 1000 x error / parallax^2.

A missing parallax is never interpreted as zero distance and never as infinity. A star without a distance is not placed in 3D, and the HUD reports how many are not placed and why.

**Known limitations.** Atlas applies no parallax zero-point correction (the global offset is about -0.017 mas; the Lindegren et al. 2021 correction needs extra columns) and uses no distance prior (the inverse is biased at low signal-to-noise; Bailer-Jones 2015). Both are negligible for the nearby set and matter for distant stars; that is why marginal distances are flagged.

## 5. Photometry

Apparent magnitudes are published G, BP and RP. Their uncertainties are **derived** from the published flux signal-to-noise ratio, sigma = 1.0857/SNR, and exclude zero-point calibration. Absolute G magnitude is derived as M = G - 5 log10(d) + 5 with **no interstellar extinction**.

## 6. Quality and validation

Hard validation rejects a record only if it is physically or structurally invalid (`src/data/ingestion/normalize.ts`): malformed id, duplicate id, non-finite or out-of-range coordinates, an implausible G value, negative uncertainties, an unexpected reference epoch, non-numeric text in a numeric column. A rejected record is **kept in the report in full**, with its reasons.

Everything merely questionable is **kept and flagged** (`src/data/catalogue/flags.ts`, shown in the inspector): no/invalid/unreliable/marginal parallax, no proper motion, no G, no BP/RP, RUWE > 1.4, 2-parameter solution, Gaia duplicated-source flag, implausible parallax or proper motion, Hipparcos match separation above 1 arcsec.

The full counts are in `docs/DATA_QUALITY_REPORT.md`. As of this build: 35,325 imported, **0 rejected**, 34,925 placed in 3D, 34,890 drawn, 339 with no parallax, 61 with an unreliable one, 552 marginal, 10,008 with RUWE > 1.4.

### Findings from real data
1. **Missing G is not invalid.** The first validation rule rejected 35 records for lacking a G magnitude. They are genuine nearby stars (parallax 26.5 to 138 mas, i.e. 7 to 38 pc). The rule conflated *missing* with *invalid*; it was corrected so they are kept, flagged `no-g-magnitude`, counted, and inspectable by search (they cannot be drawn without a brightness).
2. **Gaia DR3 has no source brighter than G = 1.5.** An unrestricted archive query returns zero rows. Sirius A, Canopus, Arcturus, Vega and the other very brightest stars are therefore absent from this dataset (they saturate the detector). The pipeline is faithful; the gap is the catalogue's.
3. **Spurious solutions in the Galactic plane.** Faint (G > 14) stars at 30 to 40 pc over-populate the plane. For stars within 40 pc and brighter than G = 14 (13,200 stars) the sky is isotropic as it must be: 17.7% (G < 6.5, N = 865), 17.9% (6.5 to 10, N = 2,949) and 17.4% (10 to 14, N = 9,386) lie within |b| < 10 deg, against 17.4% expected for a uniform sphere. That independently confirms the coordinate transform. Among the fainter stars at 30 to 40 pc, 57% of those in the plane have RUWE > 1.4 against 14% off the plane, the signature of crowded-field spurious astrometric solutions. They are not deleted (high RUWE also occurs for genuine unresolved binaries). The viewer can hide them with a toggle, but **the toggle only partly removes the excess**: with RUWE > 1.4 stars removed, the within-40-pc in-plane fraction is still 23.0% against 17.4% expected. Treat faint nearby stars at low Galactic latitude as contaminated. The finding is recorded as a regression test (`tests/search.test.ts`).

## 7. Duplicates and cross-identification

| Case | Handling | Count in this build |
|---|---|---|
| Same `source_id` twice | second occurrence rejected, kept in the report | 0 |
| Two Gaia sources claiming one Hipparcos number | listed, never merged. A null `hip_id` only means "not in Gaia's best-neighbour table", not "not a Hipparcos star"; conflicts are therefore a lower bound | 0 |
| Close pairs (< 0.5 arcsec, different `source_id`) | **reported, never merged**: close pairs are usually real binaries | 10 |
| Gaia `duplicated_source` flag | kept and flagged | 1,896 |
| SIMBAD returns two different objects for one Gaia id | left unmatched, listed | 0 |
| One SIMBAD object matched by two Gaia ids | both kept, listed | 1 (`2MASS J13171150+1849232`) |
| Gaia sources with no SIMBAD match | no identification; shown as "Gaia source, not classified" | 3,662 of 35,325 (10.4%) |

An unidentified Gaia source is not called a star: classification comes only from SIMBAD.

## 8. Ingestion architecture

```
Gaia TAP ──async job──▶ data/cache/<key>.csv  (+ .meta.json: time, endpoint, ADQL, SHA-256)   [git-ignored]
                               │
                               ▼  parseGaiaCsv → normalizeGaia → buildGaiaDataset
                  public/data/gaia-dr3-subset.v1.json.gz     columnar, nulls, manifest, content SHA-256
                  data/reports/gaia-dr3-subset.v1.quality.json
SIMBAD TAP ─exact id batches (cached per batch)─▶ mergeSimbad ─▶ public/data/simbad-crossid.v1.json.gz
                               │
                               ▼  report
                  docs/DATA_PROVENANCE.md, docs/DATA_QUALITY_REPORT.md
```

Code: `src/data/ingestion/` (`csv`, `tap`, `cache`, `gaia`, `simbad`, `normalize`, `crossid`, `quality`, `build`, `report`) and `tools/data-import.ts`. Only `cache.ts`, `build.ts` and the tool use Node APIs; the browser imports only `src/data/catalogue/`.

- **Reproducible:** `npm run data:rebuild` rebuilds from the cache with `--offline`, which never touches the network and fails if a cache entry is missing. The dataset records a SHA-256 of its content: identical raw input gives an identical hash regardless of build time (tested).
- **Incremental / versioned:** a changed query hashes to a new cache key, so old downloads stay valid. SIMBAD is cached per batch, so a rerun only fetches missing batches. The manifest carries a `version` and the format a `formatVersion`; readers reject unknown versions.
- **Politeness and credentials:** anonymous access only, no keys anywhere. 400 ms between SIMBAD requests. A generic user agent that names no person.
- **Runtime:** the browser fetches two static files. No catalogue request is made per star or per frame.

## 11. Known limitations (stars)

- **The visible density is a selection effect.** The sample is every Gaia DR3 source with parallax >= 25 mas and parallax/error >= 5, plus every source brighter than G = 6.5 at any distance. Gaia itself is incomplete for the faintest nearby dwarfs, for close binaries and for the very brightest stars, and noisy parallaxes make the 40 pc edge fuzzy, so even the nearby set is not a complete census. Densities, luminosity functions and structure must not be read from the viewer. The application says so on screen.
- Magnitude-limited, not volume-limited: the bright set reaches kiloparsecs, the nearby set stops at 40 pc.
- The brightest stars (G < 1.5) are absent from Gaia DR3.
- Binary and multiple systems appear as separate sources; no orbit or system model.
- No extinction, no radial velocity, no epoch propagation, no zero-point correction, no distance prior.
- About 61% of records lack a GSP-Phot temperature; colour comes from BP-RP, and 1,372 records lack BP and/or RP.
- SIMBAD data came from the mirror, not the primary host, on the retrieval date.
- The old hand-entered Solar System seed (`src/data/seed.ts`) remains unverified, but nothing in the application reads it any more: the Solar System now comes from the JPL import.

## 12. The Solar System dataset
The Solar System is a second dataset built by the same principles: build-time import from authoritative sources, local files at runtime, provenance on every value, and explicit "unavailable" instead of invented numbers. Methodology, sources, orbital models, accuracy and limitations are in `docs/SOLAR_SYSTEM.md`; the measured model error against JPL Horizons is in `docs/SOLAR_SYSTEM_VALIDATION.md`; texture provenance is in `docs/TEXTURE_PROVENANCE.md`.

| Topic | Convention |
|---|---|
| Sources | JPL Horizons (physical data, osculating elements, validation vectors), JPL SSD (approximate planetary elements, satellite mean elements), NAIF `pck00011.tpc` (IAU orientation), NASA Science (the Sun's spectral type; SIMBAD does not catalogue the Sun) |
| Frame and axes | Heliocentric (planets) or parent-centred (satellites), ICRS-aligned, so planets share axes with the Gaia catalogue frame |
| Units | SI in the dataset where JPL uses them (km, kg, K); catalogue-native units are preserved and shown with their unit |

| Missing | absent from the measurement table and listed with a reason; never zero |
| Uncertainty | JPL's published values where given; a derived mass carries the uncertainty of G (about 2.2e-5), which dominates |
| Reproducibility | `npm run data:solar:offline` rebuilds from `data/cache/solar` with no network; the validation table is regenerated each build |

### 13.2 Licence concerns found
These are findings, not conclusions. Item 1 was handled by withdrawing the affected images and item 8 records a re-check of seven image licences; the rest have not been resolved with the archives and should be checked before a public release.
1. **Gaia: three statements; the two derived images were withdrawn.** The Gaia DR3 documentation ("Credit and citation instructions") says the data are "open and free to use, provided credit is given to ESA/Gaia/DPAC". The Gaia Users licence page (cosmos.esa.int/web/gaia-users/license) says the data are distributed under CC BY-NC 3.0 IGO, that is non-commercial. The point-catalogue manifests for the cluster members record "CC BY-SA 3.0 IGO" for the underlying Gaia data. These do not agree. The two Gaia density maps (`lmc-gaia-density`, `smc-gaia-density`) were derived by us from DR3 counts. Because unrestricted redistribution could not be confirmed (the Users page points to separate terms for commercial use) they were withdrawn on 2026-11-12: the image files, the manifest entries, the provenance records and the credits entries are gone, and the SMC now has no image. They can return only if the project is accepted as non-commercial. The 35 325-star Gaia subset (sections 1 to 11) and the cluster member point catalogues (manifests record CC BY-SA 3.0 IGO) remain Gaia-derived and carry the same open question, as noted in the roadmap.
2. **NED-D "All Rights Reserved".** The NED-D file carries a copyright header. We store individual distances with attribution (the usual scientific practice), and do not redistribute the table. Whether that suffices for the M87 and M81 distances was not confirmed with NED.
3. **Zenodo and VizieR.** The Zenodo member lists are CC BY 4.0 (clear). VizieR tables are served under the CDS "free to use with acknowledgement" terms; the original publication licences were not read table by table.
4. **Legacy Surveys.** CC BY 4.0, but the credit wording is prescribed and must stay unaltered and visible (shown in the image-credits line and on `public/credits.html`).
5. **NASA and ESA/Webb images.** All Webb and Hubble images used here were taken from ESA/Hubble and ESA/Webb, whose pages state CC BY 4.0 with no exception on the image page; credit lines name NASA, ESA, CSA, STScI and, for some, third parties. No image is taken from NASA's own site, where per-image copyright can differ.
6. **HyperLEDA and the Baumgardt table** state no terms on the pages used. Only individual values are quoted, with attribution.
7. **Image validator.** The image validator requires `redistributionAllowed: true`. That flag is a yes/no gate and should be read together with the evidence text (it was the Gaia maps' evidence that carried an NC note; they are withdrawn).
8. **Re-verification of seven ESA/ESO assets (2026-11-12).** `47-tucanae-vista-ir`, `cen-a-eso-multiband`, `cen-a-eso-wfi`, `m31-phat-visible`, `m33-vst-visible`, `m81-hubble-acs` and `m104-hubble-acs-mosaic` had carried only the site-wide licence sentence. Each image's own page was fetched (HTTP 200) and none shows a non-commercial, third-party-copyright or no-redistribution notice; the page's credit line equals the stored credit; the evidence now quotes the usage page's licence sentence and credit-line answer and gives the date. Weakest case: `cen-a-eso-multiband`, whose credit names MPIfR/APEX and NASA/CXC with no separate rights notice on the page; accepted with those names kept in the credit. The ESO licence link is unified to `https://www.eso.org/public/outreach/copyright/` (the link the ESO pages carry; the older `/public/copyright/` serves identical text). Metadata corrected: the Orion VISTA credit regained its acknowledgment line and the Ring Nebula Hubble credit now uses the page's apostrophe. Limits: the ESO/ESA licences have an "unless specifically noted" clause, so this is true as of that date; the credit-line comparison was not run for the 9 GALEX assets or the Legacy Surveys cutout (the Legacy Surveys acknowledgment page shows CC BY 4.0; the SkyView "Public domain" sentence was not re-read).

### 13.3 Conventions
| Topic | Convention |
|---|---|
| Positions | ICRS J2000 right ascension and declination in degrees, catalogue-native, not propagated to another epoch. Cartesian positions are derived on load (`src/core/deepspace/geometry.ts`), never stored |
| Units | Distances kept in the source's unit (pc, kpc, Mpc); redshift as cz in km/s; angular sizes in arcmin; magnitudes in the catalogue's band. A physical size is `2 d tan(theta/2)` |
| Categories | **observed**: a published measurement used as printed (RA/Dec, a Cepheid distance, a Gaia parallax). **derived**: arithmetic on published values with the transformation recorded (physical diameter, absolute magnitude without extinction correction, age in Myr from log age, a distance from a distance modulus or a Gaia EDR3 geometric distance, a distance error propagated from a distance modulus error). **modelled**: a value from a fitted or analytic model (globular-cluster mass from N-body fits, Milky Way parameters, and the dust-cloud distances of Orion, Horsehead, Eagle and NGC 1999 from the Zucker et al. 2020 3D dust-extinction model) |
| Distance uncertainty | Always kept. Where a paper gives statistical and systematic terms the stored value is their quadrature sum and the note says so; asymmetric intervals are stored as the mean half-width with the asymmetric values in the note; the McConnachie error is the mean of the upper and lower catalogue errors. UNGC publishes none on the adopted distance, so it is null except for 299 rows with a single matching distance-modulus measurement (our first-order propagation). A distance without a published error carries no invented one, and the viewer says so. Exceptions of ours, written into each measurement's `transformations`: the Zucker nebulae take the median of all catalogued sightlines within 1.0 deg and an uncertainty of sqrt((half the sightline range)^2 + (median catalogue error)^2), a descriptive scatter (NGC 1999 has one sightline, so its uncertainty is that sightline's own error); cluster physical diameters carry no uncertainty, because a membership-defined size has none published and the distance error alone would mislead |
| One distance per object | One primary measurement per named object is drawn; the other values SIMBAD lists and the spread of NED-D records are in the object's facts so the drawn value is not mistaken for the only one |
| Redshift distances | `d = cz/H0` is a Hubble-flow estimate. H0 = 70 km/s/Mpc is an application choice, not a catalogue value. Peculiar velocities are not removed. Rows with cz below 1000 km/s are not placed by cz. The 2MRS file reaches cz = 51 864 km/s, 741 Mpc at H0 = 70 (median of the placed rows 121 Mpc), farther than the 600 Mpc camera limit |
| Missing values | Absent from the measurement table and listed in `unavailable` with a reason; never zero. `diameterArcmin` is null for every McConnachie row because only a half-light radius is published |
| Morphology | The catalogue's own string is kept (`morphologyLabel`); the coarse class used for rendering comes from `classifyGalaxy`, which refuses ambiguous labels. One exception: the Milky Way has no catalogue entry, so its label is the literature range "SBb - SBbc" (Kormendy 2019) with a `morphologyNote` saying it is not a catalogue string, and `morphologyClassBasis` ("SBbc") is the string that is classified |
| Disc orientation | Inclination and position angle with source; `nearSide` is `unknown` for every galaxy in the data (none of the sources retrieved states it) |
| Reproducibility | `npm run data:objects:offline` and `npm run data:deepspace:catalogues:offline` rebuild from `data/cache/deepspace/`; the build validates before writing and fails on any error |

### 13.4 Observed, derived, modelled by dataset
| Dataset | Class | Note |
|---|---|---|
| Named-object positions, distances, magnitudes, radial velocities | observed (distances may be derived from a modulus) | Per-quantity sources in the objects document |
| McConnachie 2012 (101 rows), UNGC (869 rows) | observed (compilation), distances as adopted by the authors | Compilations, not complete surveys; UNGC covers about 11 Mpc with a few velocity-based entries beyond |

| Cluster physical diameters | **derived** from an angular size of stated definition and the cluster distance | No uncertainty stored (see 13.3) |

### 13.5 Known data gaps
- Near side of every disc galaxy (tilt direction).
- Angular size for Carina and NGC 1999 (SIMBAD lists none); nebula angular sizes from SIMBAD are indicative extents, not calibrated edges.
- Integrated V magnitudes for the extended nebulae; emission-line statements for Eagle, Carina and Horsehead; globular-cluster ages (the VizieR table was not served by the mirror); open-cluster masses.
- A Local Group barycentre, a group distance and a group position (none published in the sources used).
- Images for the Pleiades, Hyades, Omega Cen, M13, M4 and for the groups; the SMC has no image since the Gaia maps were withdrawn; higher-fidelity images for M32 and M87.
- NED-D is a 2020 compilation; later distances are missing.
- The 2MRS file is limited to galaxies with a redshift (1 066 rows without one were dropped), and the globular-cluster files to 20 000 members. The camera cannot be more than 600 Mpc from its focus although the 2MRS sample reaches 741 Mpc.
- No spectroscopic survey deeper than 2MRS (DESI, SDSS) is integrated.

### 14.3 Other objects (`public/data/other-objects.v1.json`)
Six objects: Sagittarius A*, Cygnus X-1, Crab Pulsar, SN 1987A, Eta Carinae, Vela Pulsar. Positions from SIMBAD (epoch-2000 values, not propagated; the Cygnus X-1 position is that of its optical component HD 226868). Each distance is a published value from one arXiv abstract named in the file and checked against the fetched abstract at build time; Sagittarius A* uses the same 8,178 pc as the Milky Way model. Asymmetric published errors are stored as the larger side. Eta Carinae's distance is contested (the file says so). SIMBAD terms were not fetched.

### 14.4 Notes and relations (`public/data/discovery-notes.v1.json`, `relations.v1.json`)
69 notes, 405 claims, 140 distinct reference URLs, each claim with a status (observed, inferred, hypothesis, historical) and a retrieval date. They paraphrase NASA, ESA, ESO and arXiv pages and SIMBAD and archive queries; they are not independent measurements and were not re-verified against full page texts (for arXiv only abstracts were read). Source lists: `docs/DISCOVERY_NOTES_SOURCES_SOLAR_DEEP.md`, `docs/DISCOVERY_NOTES_SOURCES_STARS_EXO.md`. Where a note's source differs from the atlas value, the note says so (Orion, Eagle, Ring, Horsehead, Veil, LMC, M104, M4 distances; M104 morphology). M81 and M32 each rest on a single NASA page. Five curated relations each cite a paper.

### 14.6 Caveats of the combined atlas
- A star in several datasets is one record; its values may come from more than one dataset (`source` on the measurement says which). Gaia wins, then Hipparcos, then the exoplanet host.
- Gaia, Hipparcos and the archive each have their own distance for a star; when they disagree the winner's distance is used and the others are not shown. No averaging is done.
- The Gaia licence question of section 13.2 applies to every Gaia-derived record the engine searches.
- Every list and filter says it covers the records held in the atlas. Counts such as "nearest stars" are not a census of the sky.
